# 《罗刹当铺》UI 设计方案

版本：v1.0  
项目：罗刹当铺 H5 小游戏  
技术栈：React + Vite + Tailwind CSS + Framer Motion + html2canvas  
用途：比赛交付复盘、对外展示、后续开发交接

## 1. 设计定位

《罗刹当铺》的 UI 不是普通工具界面，也不是营销落地页。它是一段 90 到 120 秒的志怪交互体验，用户从“雾门外”进入“当铺内”，完成摇签、认命、典当、取物、续签、得票、离店。

因此 UI 的核心目标不是“解释功能”，而是让玩家相信自己真的走进了一间只在夜里开门的当铺。

设计关键词：

- 聊斋骨
- 旧纸感
- 木质旧物
- 朱砂印
- 烛光
- 雾
- 账本
- 掌柜
- 命数
- 一夜故事

明确避开的方向：

- 科技蓝、紫色渐变、霓虹光效
- 现代塑料按钮
- 过度卡片化的 SaaS 风
- 说明书式教程
- 亮白背景和强商业感布局

## 2. 视觉原则

### 2.1 先有场景，再有界面

早期版本更像网页表单，流程能跑，但“不像一间当铺”。后续视觉升级的第一条原则是把页面从“组件堆叠”改成“场景承载”。

关键做法：

- 开场使用当铺远景图，先让玩家看到门。
- 入店后切到店内主视觉，柜台、货架、签筒都在同一个空间逻辑里。
- 命格卡、当票卡保留独立卡面，但周围仍处在夜铺环境中。
- 所有按钮和面板都压低现代 UI 感，让它们像当铺里的纸、木、印、票。

### 2.2 位图负责气氛，CSS 负责交互

项目使用 AI 位图承担大氛围，包括当铺远景、店内主场景、掌柜剪影、4:3 展示图。交互部件则尽量用 React、CSS 和 SVG 实现。

这样做有三个好处：

1. 场景统一，第一眼有完整世界感。
2. 可交互道具不会被图片裁剪限制。
3. 后续改动画、改尺寸、改状态，不必反复重做整张图。

典型例子是签筒。最初尝试从背景图裁切签筒，结果位置、边缘、透底都不理想。最终改成重新生成独立签筒素材，并让签筒和弹出签保持同一旧竹木质感。

### 2.3 色彩克制，靠材质区分层级

主色并不追求丰富，而是控制在一组稳定材质内：

- 深褐：夜色、木柜、背景压暗
- 暖棕：纸面、灯火、桌面
- 宣纸黄：命格卡和当票卡
- 朱砂红：印章、重点边框、命格强调
- 墨色：正文、账目、二维码

层级不是靠彩虹色区分，而是靠纸张深浅、边框粗细、阴影厚度、朱砂占比区分。

## 3. 核心界面设计

### 3.1 开场：雾门一开

目的：让玩家在点击前先进入故事状态。

设计方式：

- 使用当铺远景图作为第一屏。
- 门内透出暖光，外部用深色和雾气包裹。
- 标题“罗刹当铺”不放在卡片中，而是直接压在场景上。
- 按钮像旧木牌或朱砂封签，避免现代 CTA 感。

经验：开场不要急着解释规则。第一屏只做一件事，让玩家愿意推门。

### 3.2 入门问话：客从何处来

这一段补足故事性。玩家不是直接进入功能菜单，而是先被掌柜问来意。

两个入口：

- 来此逛逛
- 有烦恼事欲解脱

这不是普通分支按钮，而是把玩家的心理姿态写入后续命格生成、掌柜口吻和故事记录中。

经验：同样是选择项，如果它有叙事身份，就比“开始游戏”“下一步”更有代入感。

### 3.3 摇签问命：道具是主角

摇签界面是最需要“相信感”的节点。

最终设计：

- 店内桌面背景承载签筒。
- 签筒居中，保持旧竹木材质。
- 点击后签筒摇晃。
- 随后弹出一支与筒内竹签同质感的签。
- 取签后朱砂命印盖落，再进入命格卡。

关键修复：

- 不再从背景图硬裁签筒。
- 不让签筒跑到背景图原签筒位置。
- 弹出的签不用普通 SVG 质感，而要和签筒里的竹签统一。

经验：核心仪式道具不能“差不多”。玩家会盯着它看，材质错一点，世界感就塌一块。

### 3.4 命格卡：像签，也像朋友圈人格卡

命格卡承担两件事：

1. 游戏内告诉玩家“你今夜是什么命”。
2. 游戏外让玩家愿意截图或导出分享。

卡面元素：

- 命格名
- 判词
- 签背小字
- 命签小传
- 分享钩子
- 五项命数
- 九两九钱印记
- 故事二维码

设计重点：

- 判词要短，一句话直击人心。
- 小传要有“这是我的故事”的感觉。
- 卡面要像旧纸签，不像心理测试报告。
- 二维码只放在故事生成后的命格卡导出版本里，避免初始命格卡空扫。

经验：分享卡不是把数据排整齐，而是要让用户觉得“这句话替我说了”。视觉上要留出情绪余白。

### 3.5 货架与典当：让选择像交易

货架是游戏的选择场。每件物品都不是道具说明，而是“人生中某种不肯承认的东西”。

设计方法：

- 商品按档位区分质感，不用强烈色块。
- 低档轻、上品暗金、镇店物用朱砂边。
- 价格严格用痴、嗔、贪、惘、慧和两/钱制。
- 鼠标悬停有轻微浮起、光影变化和音效。
- 取物后出现获得浮层，展示副作用和命数变化。

经验：交易系统最怕像商城。这里的货架不是购物车，而是柜台上的诱惑和代价。

### 3.6 当票卡：一局的收束

当票卡是最终分享物，也是故事落点。

卡面元素：

- 当铺标题
- 命格
- 当票故事
- 交易摘要
- 五项命数变化
- 临别赠言
- 朱砂“当”印
- 命主故事二维码

迭代中修过两个问题：

- 朱砂印与二维码重叠。修复方式是把印章上移，右下角留给二维码。
- 二维码过大遮挡内容。修复方式是回到小尺寸，同时保留高清二维码生成。

经验：分享卡上的二维码是入口，不是主角。它必须可扫，但不能抢走故事和临别金句。

### 3.7 命主故事页：分享后的第二落点

v1.5 新增 `/story/{storyId}`，让二维码不只是装饰，而是进入一篇“一夜笔记”。

页面设计：

- 纯只读
- 不显示账号、昵称、头像
- 不评论、不点赞、不排行
- 宣纸面板承载故事正文
- 保留“我也走一遭”回到首页

经验：故事属于那一夜，不属于某个用户。UI 上不要做社交平台感，否则会破坏当铺的克制。

## 4. 动效设计

动效不是为了炫，而是为了让节点有重量。

已使用的动效：

- 开场雾气漂移
- 推门入店的 scale、blur、fade
- 屏幕切换的墨幕题词
- 签筒摇晃
- 竹签弹出
- 朱砂印盖落
- 卡片入场和悬停
- 取物浮层
- 当票展开
- 数值变化 CountUp

参考《夜巡录：荒庙篇》的经验时，只吸收方法，不复制代码和素材。核心是把“网页流程”变成“游戏反馈”：每一次点击，都要有声音、画面或状态上的回应。

## 5. 音频设计

音频分两层：

- 背景音乐：使用项目本地 `luocha.mp3`，营造志怪夜铺氛围。
- 程序化音效：按钮、纸页、落印、典当、取物、续签、离店，用 Web Audio API 实时生成。

经验：

- 音乐不能抢文字。
- 点击反馈要短。
- 摇签、落印、当票这些节点要有“手感”。
- 背景音乐一旦方向不对，整体气质会立刻偏掉，所以后来把 BGM 改回原来的罗刹当铺音频。

## 6. 内容与 UI 的关系

这个项目的 UI 不是孤立美术。它必须服务文案和 LLM 生成内容。

关键做法：

- 开头先问“客从何处来，到店有何事”。
- 命格卡要像 MBTI 式的个人投射，但不使用现代人格测试词。
- 掌柜台词要短、狠、留余味。
- 当票卡要从“结算结果”升级为“故事凭证”。
- 临别金句要像朋友圈配文，而不是系统评价。
- 二维码把分享卡变成故事入口。

经验：如果文案不击中人，UI 再像古风也只是皮肤。真正能让用户转发的，是视觉和一句话同时说中他。

## 7. 主要迭代经过

### 7.1 第一阶段：能玩

先跑通完整主流程：

- 开场
- 摇命牌
- 命格卡
- 入门典当
- 自由交易
- 续签
- 当票卡
- 离店

这一版功能完整，但视觉上更像 H5 表单。

### 7.2 第二阶段：像游戏

增加：

- 场景背景
- 雾门过渡
- 掌柜剪影
- 货架分级
- 取物反馈
- 当票拼合
- BGM 和音效

这一阶段让项目从“流程图”变成“可相信的游戏体验”。

### 7.3 第三阶段：像罗刹当铺

重点修气质：

- 签筒换成独立旧竹木材质。
- 弹出签与筒内竹签统一质感。
- 补掌柜问来意。
- 补九两九钱世界观暗线。
- 补节气与夜维度。
- 补命主故事和二维码入口。

这一阶段解决的是“它是不是独属于这个题材”的问题。

## 8. 踩坑记录

### 8.1 背景裁切不能替代道具设计

从背景图裁签筒会遇到三个问题：

- 边缘不干净
- 位置不受控
- 和交互动画脱节

最后改为独立素材和组件化交互，这是正确方向。

### 8.2 二维码不能只考虑能生成

二维码经历过两类问题：

- 太大，遮挡当票内容。
- 内容太长，导致二维码不显示或难以识别。

最终方案：

- 卡片二维码只放短链接 `/story/{storyId}`。
- 兜底长链接留给按钮，不拿来生成二维码。
- 二维码视觉尺寸控制在卡片的角落入口角色。

### 8.3 朱砂印不能压住信息

朱砂印是情绪重点，但不是内容主体。它一旦压住二维码或账目，视觉就变成干扰。

修复方式：

- 最终卡内印章上移。
- 右下角留给二维码。
- 盖印动画短暂出现后淡出，不在最终画面中制造双印。

### 8.4 本地故事可读不等于扫码可读

本地 `localStorage` 只能被当前浏览器读到。手机扫码打开同一个 storyId 时，没有这份缓存。

解决方向：

- 生产环境使用 KV 持久化。
- 未配置 KV 时，按钮可用 URL payload 兜底。
- 卡片二维码保持短链接，避免过长失效。

## 9. 可复用经验

1. H5 小游戏不要先做 UI 组件库，要先做世界入口。
2. 古风不是加毛笔字，而是统一材质、节奏和说话方式。
3. 分享卡要先有一句能发朋友圈的话，再谈排版。
4. 核心道具必须独立设计，不能从背景里随便抠。
5. 动效要围绕关键仪式点，不要平均撒在所有元素上。
6. 视觉资产要有 fallback，比赛现场不能因图片加载失败翻车。
7. LLM 内容需要 UI 出口，二维码和故事页就是出口。
8. 管理后台可以朴素，但玩家侧必须保持世界观纯度。
9. 声音是“像游戏”的关键，不是装饰。
10. 每次修视觉问题都要问：它是在增强当铺，还是在把当铺拉回网页？

## 10. 后续 UI 优化方向

短期：

- 给命格卡二维码增加“故事生成中”的占位状态。
- 当票卡在移动端做更精细的排版压缩。
- 后台金句审核页再统一成当铺账房风格。
- 生成一套固定截图用于参赛材料。

中期：

- 做节气商品的轻量版视觉入口。
- 给不同命格类型增加细微卡面纹理差异。
- 增加故事页的当票缩略图。
- 优化二维码与微信内置浏览器的识别和打开体验。

长期：

- 建立一套“志怪 H5 UI 资产规范”。
- 把命牌、当票、货架、掌柜、签筒做成可复用组件包。
- 形成独立游戏 demo 快速生产流程。
