# 罗刹当铺 · 引导文案与触发规则（v1.2）

> **v1.2 修订说明**：v1.1 中玩家选项"旧识老朽"违反文言礼仪——"老朽"是掌柜对自己的自谦，玩家不能用此词称呼对方。修订为"旧识掌柜"——玩家用敬称指代店主。掌柜问话仍保留"老朽"作为自称，构成"掌柜自谦 + 客敬称"的对应关系，符合文言礼仪。
>
> **v1.1 修订说明**：v1.0 流程顺序有误——把"客从何处来"放在了摇签后。
> 实际游戏流程是：推门入店 → 客从何处来 → 摇签求命 → 命格落案 → ...
> v1.1 修正此错误，并将"二选一身份界面"与"命数引导话"合并为一个界面。
>
> 本文档解决问题：玩家进店后，不知道命数是货币、不知道商品价格怎么读、不知道为什么按钮灰掉。
> 解决方案：在关键节点用掌柜的话引导，但**不破坏世界观**、**不强制教学**、**不识别用户**。
> 核心机制：让玩家自己选"初临此地"或"旧识掌柜"。

## 一、当前游戏完整流程（修正后）

```
1. 推门入店
2. 客从何处来（"来此逛逛" / "有烦恼事欲解脱"）
3. 摇签求命
4. 命格落案（朱印盖落 + 五项命数显形 + 命格判词）
5. 【新增】身份二选一 + 命数引导（合并界面）
6. 入门典当
7. 货架交易（2-3 笔）
8. 续签（可选）
9. 当票离店
```

**关键点**：

- "客从何处来"在摇签**之前**——这一步问的是来意，是玩家进店的第一个选择
- "二选一身份界面"在命格落案**之后**——这是新增的引导节点

## 二、核心设计：身份二选一界面（修正后）

### 2.1 触发位置

**命格朱印盖落 + 五项命数显形 + 命格判词淡入完成后，1.5 秒过渡**。

不在更早的位置——抽签和命格朱印是这个游戏最有仪式感的瞬间，不能被打扰。

不在更晚的位置——入门典当本身就是最容易卡住的地方，必须在这之前问。

### 2.2 界面文案（合并版本）

```
[命格朱砂未干，掌柜抬眼]

客官身上有命数九两九钱，
痴嗔贪惘慧各有分量。
铺中物事，皆以此称量。

客官初临此地，还是旧识老朽？

  [ 初临此地 ]    [ 旧识掌柜 ]
```

**称呼说明**（重要）：

- 掌柜问话用"**老朽**"——这是掌柜对自己的自谦
- 玩家选项用"**旧识掌柜**"——这是玩家对店主的敬称
- 两边称呼不一致但语义对应同一人——**这是文言礼仪的常见用法：自称用谦辞，他称用敬辞**

错误写法：

- ❌ 玩家选项写"旧识老朽"——等于玩家直呼对方为"老头"，不敬
- ❌ 掌柜问话写"旧识掌柜"——掌柜自称"掌柜"也合理，但失去自谦的层次感

正确写法见上。

### 2.3 文案分两层

**第一层（铺垫）**：前三句"命数九两九钱"——这是**世界规则的陈述**，不是新手教学，所以**两条路径都显示一次**。

**第二层（询问）**：后一句"初临此地，还是旧识老朽"——这是**玩家的身份自报**，决定后续 4 个节点的引导显示。

合并的好处：

- 少一次淡入淡出，体验流畅
- 命数规则本来就是两条路径都该听的内容
- 二选一前有铺垫，玩家不会愣住

### 2.4 选项行为

- **初临此地** → 进入"引导模式"，后续 4 处节点会显示完整掌柜话
- **旧识掌柜** → 进入"自便模式"，后续节点只显示极简提示或纯氛围文案

### 2.5 关键设计点

- **这个选择只在本局有效**——不存储任何状态，不识别用户身份
- **玩家完全自由**——头一回的人可选"旧识掌柜"，老玩家可选"初临此地"，没有任何后果
- **不弹"再次确认"**——选了就走，不允许返回修改
- **二选一不可跳过**——必须做出选择才能进入下一步

### 2.6 视觉风格

- 朱印效果延续从命格卡过渡而来
- 前三句铺垫文字与命格判词字号一致
- 二选一询问句字号稍大（突出选择重要性）
- 两个选项按钮等大、等距、等权重——**不引导玩家选其中一个**
- 全程无 emoji、无引导箭头、无"推荐"标记

## 三、四处节点的引导文案

### 节点一：入门典当界面

**触发**：玩家选"有烦恼事欲解脱"或"来此逛逛"后进入典当界面

**引导话**（**仅初临此地路径显示**）：

放在界面顶部，"哪一项命数"选择栏上方：

> 客官身上哪一份最重？
> 取出一份，老朽给你称一称，换些别的。

**为什么这两句**：

- 第一句**重新框架问题**——把"选 4 个表单字段"变成"选哪一份最重"。这把任务从填表变成自省。
- 第二句**说清楚动作的本质**——"用 A 换 B"。

**已有的损耗提示**保留（已经在 UI 上显示"一两入柜，七钱出门"）：

> 一两入柜，七钱出门。
> 罗刹海市从不做足秤买卖。

这一句两条路径都显示——它是世界观规则，不是新手教程。

---

### 节点二：货架首次打开

**触发**：典当完成、玩家第一次看到 24 件商品的货架

**引导话**（**仅初临此地路径显示**）：

在货架顶部淡入一次，玩家滚动后消失：

> 货架上每件物事，标着要几钱什么。
> 客官身上够，便取得走。

**为什么这两句**：

- 第一句解释**价格标签的读法**——"贪 3 钱"的意思是"需要花 3 钱贪"
- 第二句解释**购买条件**——"够则取，不够则不能"

**旧识路径**：不显示，玩家自己摸索。

---

### 节点三：玩家想买但命数不足

**触发**：玩家点击商品的"取此物"按钮，但对应命数不足

**引导话**（保留你之前定的）：

> 典无可典，何以为买？

**两条路径行为差异**：

| 路径 | 显示内容 |
|---|---|
| 初临此地 | 掌柜话 + UI 微提示"客官痴尚缺 2 钱" |
| 旧识掌柜 | 仅显示掌柜话 |

**UI 微提示规范**（仅初临路径）：

- 出现位置：商品标签下方或灰按钮旁
- 文案模板：`客官{命数名}尚缺 {数值} 钱`
- 字号：比商品价格稍小
- 颜色：与朱砂红同色系但稍淡，避免过度警示

---

### 节点四：续签界面

**触发**：玩家完成 3 笔交易，桌上多出一支签

**引导话**：

| 路径 | 文案 |
|---|---|
| 初临此地 | "三笔已毕。<br>桌上多出一支签——抽，则再做一笔；不抽，便就此结当。<br>上签照旧，中签加倍，下签折慧。" |
| 旧识掌柜 | "桌上又多一支签。" |

**关键差异**：

- 初临路径**完整说明**三种签的后果
- 旧识路径**只点画面**——"桌上又多一支签"，玩家自己悟

## 四、"客从何处来"界面（不动）

按 v1.1 修订，"客从何处来"在摇签**之前**发生，此时玩家尚未抽到命格、尚未自报身份。

**这一步保持游戏现状，不做任何修改**。

副标题文案沿用现有版本：

| 选项 | 副标题 |
|---|---|
| 来此逛逛 | 雾里灯亮，随手翻一页命牌 |
| 有烦恼事欲解脱 | 把一件放不下的东西，交给柜上称一称 |

理由：

- 此步问的是来意，世界观文案更贴
- 摇签前玩家还没进入"交易心智模式"，不需要直白说明
- 真正需要直白说明的是后面的入门典当和货架——已由节点一、节点二覆盖

## 五、引导词的设计原则

以下是所有掌柜话必须遵守的原则：

### 5.1 不教学，只暗示

- ❌ "请点击这里典当"
- ❌ "您可以从这五项中选择一项作为典当物"
- ✅ "客官身上哪一份最重？"

### 5.2 只在卡点说话

不在每一步都加掌柜话。**玩家能自己走的地方，让他自己走。**

### 5.3 不重复

同一个提示在同一玩家面前最多显示一次。**第二次回到这个界面就不再显示**。

实现方式：sessionStorage 临时记一下本局已显示过的引导节点 ID，**离店后清空**。**不跨局存储**。

### 5.4 高级玩家可以跳过

不需要"跳过按钮"——选了"旧识掌柜"路径就自动跳过。

### 5.5 文白比例

所有引导话采用 **半文半白**：

- ✅ "客官身上哪一份最重？"（半文，玩家能懂）
- ❌ "汝身负命数，盍择其重者而当之？"（过文，玩家看不懂）
- ❌ "您身上哪项数值最高？"（过白，破坏氛围）

判定标准：**给一个没玩过的朋友看，他要能在 3 秒内理解这句话的意思。**

### 5.6 文言礼仪：自称用谦辞，他称用敬辞

写所有掌柜话和玩家选项时，必须遵守文言礼仪的基本规则——**自称用谦辞，他称用敬辞**。

**掌柜的自称**（谦辞）：

- ✅ 老朽
- ✅ 此铺
- ❌ 在下（过商业化，不符合志怪味）
- ❌ 本掌柜（过现代）

**玩家对掌柜的称呼**（敬辞）：

- ✅ 掌柜（标准敬称）
- ✅ 此铺
- ❌ 老朽（**严重错误**，等于直呼"老头"）
- ❌ 你（白话，不文）

**掌柜对玩家的称呼**：

- ✅ 客官（标准敬称）
- ❌ 你（白话）
- ❌ 来者（过冷）

**典型错误示例**：

```
玩家选项：[ 旧识老朽 ]   ← 错。玩家不能称对方为"老朽"
玩家选项：[ 旧识掌柜 ]   ← 对。玩家敬称店主
```

```
掌柜话："你今夜走得稳"           ← 错。掌柜不用"你"称客
掌柜话："客官今夜走得稳"         ← 对
```

**判定标准**：在每一句话写完之后，自问"说话人对听话人是平等？尊敬？还是对自己谦逊？"——按答案选择对应的称谓。**这是文言书写的基本素养，写文白文风必须守住**。

## 六、两条路径的完整对照表

| 节点 | 初临此地 | 旧识掌柜 |
|------|---------|---------|
| 客从何处来（摇签前）| 副标题用世界观文案 | 副标题用世界观文案（**完全相同**）|
| 命格落案后（合并界面）| 命数铺垫话 + 二选一 | 命数铺垫话 + 二选一（**完全相同**）|
| 入门典当 | 显示"哪一份最重..." + 损耗提示 | 仅显示损耗提示 |
| 货架首次 | 显示"标着要几钱什么..." | 不显示 |
| 命数不足 | 掌柜话 + 精确缺口 UI 提示 | 仅掌柜话 |
| 续签 | 完整三签解释 | "桌上又多一支签" |

**说明**：

- "客从何处来"和"合并界面"两条路径完全相同——前者发生在自报身份之前，后者前半段是世界规则陈述（不分路径）
- 真正的路径分化从**入门典当**开始

**两条路径的本质差异**：

- 初临此地 = 显式说明 + 微 UI 提示
- 旧识掌柜 = 纯氛围文案，玩家自己摸索

## 七、工程实现规范

### 7.1 状态管理

```typescript
// 仅本局有效，不持久化
type GuidanceMode = "novice" | "veteran";

interface GuidanceState {
  mode: GuidanceMode;
  shownNodes: Set<string>;  // 本局已显示的节点 ID
}
```

**关键约束**：

- 离店时（生成当票卡后）**完全清空**此状态
- 不写入 localStorage
- 不写入 cookie
- 不写入 fingerprint
- **不跨局识别**

### 7.2 节点 ID 列表

```typescript
const GUIDANCE_NODES = {
  // 合并界面（无 ID 复用，作为流程必经环节）
  AFTER_FATE_CARD_MERGED: "after_fate_card_merged",  // 命数铺垫 + 二选一

  // 后续节点
  PAWN_FIRST_TIME: "pawn_first_time",         // 入门典当首次
  SHELF_FIRST_TIME: "shelf_first_time",       // 货架首次打开
  RESOURCE_INSUFFICIENT: "resource_insufficient", // 命数不足（每次商品按钮都可触发，但每个商品仅一次）
  LOT_DRAW: "lot_draw",                        // 续签
} as const;
```

### 7.3 渲染逻辑伪代码

```typescript
function shouldShowGuidance(nodeId: string, state: GuidanceState): boolean {
  // 命数铺垫 + 二选一：必经环节，与路径无关
  if (nodeId === "after_fate_card_merged") {
    return !state.shownNodes.has(nodeId);
  }

  // 旧识掌柜路径：除节点三的掌柜话之外，全部不显示
  if (state.mode === "veteran") {
    return ["resource_insufficient"].includes(nodeId);
  }

  // 初临此地路径：本局未显示过则显示
  return !state.shownNodes.has(nodeId);
}

function markShown(nodeId: string, state: GuidanceState): void {
  state.shownNodes.add(nodeId);
}
```

### 7.4 视觉规范

- 引导话样式：与游戏内现有掌柜剪影台词相同（打字机效果、淡入淡出）
- UI 微提示样式：朱砂红同色系但稍淡（建议 #a83838，不饱和）、字号 12-13px
- 引导话和 UI 微提示**不同时显示**——避免视觉过载

### 7.5 合并界面规范

- 出现时机：命格判词淡入完成后 1.5 秒
- 出场方式：命数铺垫话先淡入（停留 2-3 秒让玩家阅读），二选一询问句和按钮再淡入
- 按钮样式：等大等距，无视觉权重差异
- 不可跳过：必须选择一个才能进入下一步
- 选择后行为：直接进入入门典当流程

## 十、验收标准

升级完成后，以下场景必须通过：

- [ ] 流程顺序正确：客从何处来 → 摇签 → 命格落案 → 合并界面 → 入门典当
- [ ] 命格落案后，必出现合并界面（命数铺垫 + 二选一）
- [ ] 合并界面前三句"命数九两九钱"两条路径都显示
- [ ] 合并界面后一句"初临还是旧识"必须二选一，不可跳过
- [ ] **掌柜问话用"老朽"作自称，玩家选项用"掌柜"作敬称**——文言礼仪正确
- [ ] "初临此地"路径下，4 处节点引导话全部显示
- [ ] "旧识掌柜"路径下，仅"命数不足"一处显示掌柜话
- [ ] 同一节点在同一局内仅显示一次
- [ ] 离店后，下一局重新进入时，所有引导状态清空
- [ ] 不向 localStorage、cookie、fingerprint 写入任何引导相关数据
- [ ] UI 微提示仅在初临路径显示
- [ ] 引导话的文白比例符合"3 秒能懂"标准
- [ ] "客从何处来"界面无任何修改
