# 罗刹当铺 · v1.5.1 抽签机制升级文档

> 这份文档专门给 Codex 用。
> 阅读对象：实施开发的人或 AI。
> 目标：在 v1.5 基础上重构抽签机制——交易上限从"混合 3 笔"改为"卖 3 + 买 3 双轨制"，三签效果重新定义。
> 本文档所有功能依然遵守一条铁则：不引入注册账号、不引入用户体系、不引入登录数据库。

---

## 一、机制总览

### 1.1 与 v1.5 的差异

| 维度 | v1.5（旧）| v1.5.1（新）|
|------|----------|------------|
| 交易上限 | 混合 3 笔（卖 + 买合计 3）| 卖 3 + 买 3 双轨 |
| 抽签触发 | 完成 3 笔后由玩家选择是否抽 | **任一类满 3 后自动跳出抽签**|
| 上签效果 | 再交易一笔，价照旧 | **撤销最后一笔 + 重做一笔（突破上限）**|
| 中签效果 | 再交易一笔，价格 ×2 | **多交易一次，买价翻倍 / 卖损耗加倍（突破上限）**|
| 下签效果 | 扣半两慧，直接收摊 | **扣半两慧（不足则扣完），仍走完离店流程**|

### 1.2 三句核心隐喻

> 人生无常——任何一次选择都是不同的命运。
> 人生有缺——难以圆满，所以有舍才有得。
> 人生有签——上签是恩赦，中签是代价，下签是命运。

这三句是这次机制升级的设计源头。所有规则细节都为这三句服务。

## 二、交易规则改动

### 2.1 双轨上限

```typescript
interface PlayerSession {
  sellCount: number;   // 卖出次数（典当），上限 3
  buyCount: number;    // 买入次数（购买），上限 3
}
```

### 2.2 卖买判定

- **卖（pawn）**：从客身上取出某项命数，置案上换得另一项命数。`sellCount += 1`
- **买（buy）**：从货架取出商品，付出命数。`buyCount += 1`

### 2.3 抽签触发逻辑

```typescript
function shouldTriggerLot(session: PlayerSession): boolean {
  // 任一类满 3 即触发
  return session.sellCount >= 3 || session.buyCount >= 3;
}
```

### 2.4 触发时机

- 玩家完成第 3 笔卖（或第 3 笔买）的瞬间
- **自动弹出抽签界面**——玩家不可拒绝
- 满足条件的那一笔交易结算完成后立即触发

### 2.5 重要约束

- **抽签前，玩家不能继续交易**——满 3 即停
- **不允许玩家选择"不抽签直接离店"**——抽签是命运，不是选择
- **抽签界面无"跳过"按钮**

## 三、上签机制详解

### 3.1 概率与效果

```typescript
interface LotResult {
  type: "shang";
  effect: "REGRET";  // 反悔
}
```

- 概率：30%
- 效果：撤销最后一笔交易，玩家重新做一笔（买卖任意）

### 3.2 撤销逻辑

撤销需要恢复以下状态到"最后一笔交易之前"：

```typescript
interface TradeSnapshot {
  resourcesBefore: ResourceMap;     // 五项命数
  resourcesAfter: ResourceMap;
  tradeType: "sell" | "buy";
  sellCountBefore: number;
  buyCountBefore: number;
  itemInvolved: ItemRecord;          // 涉及的物品
  receiptEntry: ReceiptEntry;        // 当票上的对应账目
}

function undoLastTrade(session: PlayerSession): void {
  const lastSnapshot = session.tradeHistory[session.tradeHistory.length - 1];
  
  // 恢复命数
  session.resources = lastSnapshot.resourcesBefore;
  
  // 恢复计数
  session.sellCount = lastSnapshot.sellCountBefore;
  session.buyCount = lastSnapshot.buyCountBefore;
  
  // 恢复物品（卖出的物品归还客方账面，买入的物品归还货架）
  if (lastSnapshot.tradeType === "sell") {
    session.pawnedItems.pop();  // 移除最后一笔典当物
  } else {
    session.boughtItems.pop();  // 移除最后一笔购买物
  }
  
  // 当票上对应账目移除
  session.receipt.entries.pop();
  
  // 历史记录移除
  session.tradeHistory.pop();
}
```

### 3.3 重做规则

撤销后，玩家可以做**一次新的交易**：

- 买卖任意（即使原本买已满 3，撤销后再买也允许）
- **此次交易不计入卖 3 / 买 3 上限**
- 价格照旧（无加成、无加倍）
- 完成此次交易后**直接进入离店流程**

### 3.4 反悔但不重做

玩家可以选择"反悔但不重做"——撤销最后一笔后直接离店：

```
[ 反悔此笔，重做一次 ]    [ 反悔此笔，不再做 ]    [ 不必反悔，直接离店 ]
```

三种选项都合法。

### 3.5 上签 UI 流程

```
[抽签结果显示：上签]
       ↓
"今夜难得，反悔不加价。"
       ↓
[ 反悔最后一笔 ]    [ 不必，直接离店 ]
       ↓
（如果选择反悔）
       ↓
撤销最后一笔（命数恢复 + 物品恢复 + 当票账目移除）
       ↓
显示："已反悔。客官可重做一笔，亦可直接离店。"
       ↓
[ 重做一笔 ]    [ 直接离店 ]
       ↓
（如果重做）→ 玩家做一笔新交易 → 离店
（如果直接离店）→ 离店
```

## 四、中签机制详解

### 4.1 概率与效果

```typescript
interface LotResult {
  type: "zhong";
  effect: "DOUBLE_COST";
}
```

- 概率：50%
- 效果：多交易一次，买价翻倍 / 卖损耗加倍

### 4.2 中签的"加倍"具体计算

#### 买入加倍

商品原价直接乘以 2：

```typescript
function getMidLotBuyCost(item: Item): ResourceCost {
  const newCost: ResourceCost = {};
  for (const [key, value] of Object.entries(item.cost)) {
    newCost[key] = value * 2;
  }
  return newCost;
}
```

例：原价"贪 3 钱"→ 中签下"贪 6 钱"。

**注意**：如果加倍后价格超过 99 钱（顶档商品），仍然显示加倍后价格，玩家若命数不够则按钮灰掉，"典无可典，何以为买？"。

#### 卖出加倍损耗

正常损耗 30%（1 两入柜，7 钱出门）。中签下损耗加倍至 60%（1 两入柜，4 钱出门）：

```typescript
function getMidLotSellRate(): number {
  return 0.4;  // 中签下，1 两换 4 钱（损耗 60%）
}

function getNormalSellRate(): number {
  return 0.7;  // 正常 1 两换 7 钱（损耗 30%）
}

function calculateSellOutput(amountIn: number, isMidLot: boolean): number {
  const rate = isMidLot ? 0.4 : 0.7;
  return Math.floor(amountIn * rate);  // 向下取整
}
```

例：玩家典当 1 两痴（10 钱），正常换 7 钱慧，中签下换 4 钱慧。

### 4.3 中签的交易约束

- **必须做一笔**——玩家不能"抽到中签后选择不交易"
- 这一笔不计入卖 3 / 买 3 上限
- 完成此次交易后**直接进入离店流程**

### 4.4 中签 UI 流程

```
[抽签结果显示：中签]
       ↓
"中签——再做一笔。买价翻倍，卖损耗加倍。"
       ↓
[ 再典一物 ]    [ 再取一物 ]
       ↓
（玩家做一笔交易，UI 显示加倍后的价格）
       ↓
完成 → 离店
```

### 4.5 不允许"中签但不交易"

中签是"命运给的代价机会"——必须做一笔。如果玩家命数不够任何交易，则系统自动判定为"无法交易"，进入特殊离店流程：

```
"中签——再做一笔。但客官身上已无可典，亦无可买。"
       ↓
直接离店
```

## 五、下签机制详解

### 5.1 概率与效果

```typescript
interface LotResult {
  type: "xia";
  effect: "DEDUCT_HUI";
  deductAmount: 5;  // 半两 = 5 钱
}
```

- 概率：20%
- 效果：扣慧 5 钱（半两）；若慧不足 5 钱则扣完所有慧

### 5.2 扣除逻辑

```typescript
function applyXiaLot(session: PlayerSession): void {
  const currentHui = session.resources.hui;
  const deduction = Math.min(currentHui, 5);  // 不足则扣完
  
  session.resources.hui -= deduction;
  
  // 当票上添加特殊记录
  session.receipt.specialEntries.push({
    type: "xia_lot",
    description: "今夜运气不济，扣慧" + numberToChinese(deduction) + "钱",
    huiDeducted: deduction,
  });
}
```

### 5.3 下签的离店流程

下签**不立即结束游戏**——仍走完完整离店流程：

```
[抽签结果显示：下签]
       ↓
"下签——今夜运气不济，慧折半两。便就此结当吧。"
       ↓
扣除慧 5 钱（或扣完）
       ↓
显示新的命数状态（慧的格子有红色"-五钱"标记淡入）
       ↓
[ 结当离店 ]
       ↓
生成当票卡 + 命主故事 + 离店
```

### 5.4 当票卡上的下签记录

下签的扣除应在当票卡上**单独显示一行**，与典当/购买分开：

```
夜账札记
─────────────────
典当：半嗔舍利
取物：一句迟到的对不起
续签：下签
   └ 今夜运气不济，扣慧五钱
─────────────────
```

### 5.5 命主故事中的下签处理

如果玩家抽到下签，命主故事生成时应将"下签"作为重要叙事素材。Prompt 输入中应明确传递：

```typescript
{
  drewLot: true,
  lotResult: "xia",
  lotEffect: "扣慧五钱",
}
```

LLM 应在故事中体现这一笔——例如：

> 签筒摇出下签，签面无字。掌柜执笔记账，扣慧五钱。客闻之，未语，眉间又添一霜。

## 六、抽签 UI 总流程

### 6.1 触发条件

```typescript
function checkLotTrigger(session: PlayerSession): boolean {
  return session.sellCount === 3 || session.buyCount === 3;
}
```

### 6.2 触发时机

满足条件的那一笔交易**结算完成后立即触发**——不等玩家点击"继续"或其他按钮。

### 6.3 抽签界面文案（初临此地路径）

```
[桌上多出一支签，签筒微响]

三笔已毕。
桌上多出一支签——
上签照旧，中签加倍，下签折慧。

[ 摇签 ]
```

**说明**：

- 没有"不抽"选项——抽签是命运，不是选择
- "摇签"按钮是唯一的前进路径
- 文案保留你之前定的"上签照旧，中签加倍，下签折慧"

### 6.4 抽签界面文案（旧识掌柜路径）

```
[桌上多出一支签]

桌上又多一支签。

[ 摇签 ]
```

旧识路径保持极简，玩家自己懂。

### 6.5 抽签动画

按现有摇签求命的视觉风格——签筒摇晃 1.5 秒，一支签弹出，朱印效果。

抽签结果（上/中/下）以朱砂红字显示。

### 7.1 三种签的不同记录格式

**上签**（玩家反悔且重做）：

```
续签：上签
   └ 反悔最后一笔，重做：以 1 两痴换 7 钱慧
```

**上签**（玩家反悔不重做）：

```

   └ 未反悔
```

```
续签：中签
   └ 再做一笔（加倍）：以 1 两 4 钱慧取走"一句迟到的对不起"

```

```
   └ 今夜运气不济，扣慧五钱
```

签的记录应作为单独一节，紧跟在交易记录之后、命数对照之前：

```

[命数对照]
[临别赠言]
```

## 九、跨平台迁移就绪

### 9.1 数据存储

抽签机制不引入任何持久化存储——所有签的状态（哪种签、是否反悔、是否重做）都存在 sessionStorage 中，离店后清空。

### 9.2 与命主故事的接口

抽签结果通过现有的 `FateStoryInput` 接口传递给命主故事生成 LLM：

```typescript
{
  drewLot: true,
  lotResult: "shang" | "zhong" | "xia",
  lotAccepted: boolean,        // 上签：是否反悔；中签：是否完成加倍交易
  lotRedoneTradeType?: "sell" | "buy",  // 上签：反悔后重做的类型
}
```

### 9.3 与当票卡的接口

抽签结果以独立结构存入当票数据：

```typescript
interface ReceiptData {
  // ... 现有字段
  lotEntry?: {
    type: "shang" | "zhong" | "xia";
    description: string;       // 中文描述
    redoneAction?: TradeRecord; // 上签反悔后重做的交易（如有）
    huiDeducted?: number;      // 下签扣除的慧（如有）
  };
}
```

## 十、边界情况处理

### 10.1 玩家命数过低导致无法交易

**场景**：玩家完成 3 笔卖后命数严重不足，无法买任何东西。中签强制再做一笔但买不起也卖不了。

**处理**：

```
"中签——再做一笔。但客官身上已无可典，亦无可买。"
       ↓
"罢了。便就此结当吧。"
       ↓
直接进入离店流程
```

### 10.2 上签反悔后玩家选择"不重做"

**场景**：玩家反悔了最后一笔，但选择不再做新的一笔。

**处理**：直接进入离店流程。当票上记录"反悔最后一笔，未再做"。

### 10.3 下签时慧已为 0

**场景**：玩家抽到下签，但慧已经是 0 钱。

**处理**：扣 0 钱（即不扣）。当票记录"今夜运气不济，但慧已尽，未能再扣"。

### 10.4 上签反悔时无可反悔（理论上不存在）

**理论场景**：玩家在没有任何交易的情况下抽到上签。

**实际**：此场景不会发生——抽签触发条件是"卖 3 或买 3 满"，至少已有 3 笔交易。

如果出现此 bug 的边界情况：UI 显示错误，无可反悔则不显示反悔按钮，仅"直接离店"。

## 十二、核心隐喻（保存）

> **人生无常**——任何一次选择都是不同的命运。
> **人生有缺**——难以圆满，所以有舍才有得。
> **人生有签**——上签是恩赦，中签是代价，下签是命运。

这三句应在以下位置体现：
