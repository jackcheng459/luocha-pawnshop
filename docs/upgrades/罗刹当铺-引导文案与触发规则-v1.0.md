# 罗刹当铺 · 引导文案与触发规则

> 本文档解决一个真实问题：玩家进店后，不知道命数是货币、不知道商品价格怎么读、不知道为什么按钮灰掉。
> 解决方案：在关键节点用掌柜的话引导，但**不破坏世界观**、**不强制教学**、**不识别用户**。
> 核心机制：让玩家自己选"初临此地"或"旧识老朽"。

---

## 一、核心设计：身份自报机制

### 1.1 触发位置

命格卡落案之后、入门典当之前。

**不在更早的位置**——抽签和命格朱印是这个游戏最有仪式感的瞬间，不能被打扰。

**不在更晚的位置**——入门典当本身就是最容易卡住的地方，必须在这之前问。

### 1.2 界面文案

```
[命格朱砂未干，掌柜抬眼]

客官初临此地，还是旧识老朽？

  [ 初临此地 ]    [ 旧识老朽 ]
```

### 1.3 选项行为

- **初临此地** → 进入"引导模式"，后续 6 处节点会显示完整掌柜话
- **旧识老朽** → 进入"自便模式"，后续节点只显示极简提示或纯氛围文案

### 1.4 关键设计点

- **这个选择只在本局有效**——不存储任何状态，不识别用户身份
- **玩家完全自由**——头一回的人可选"旧识"，老玩家可选"初临"，没有任何后果
- **不弹"再次确认"**——选了就走，不允许返回修改
- **二选一不可跳过**——必须做出选择才能进入下一步

### 1.5 视觉风格

- 朱印效果延续从命格卡过渡而来
- 两个选项按钮等大、等距、等权重——**不引导玩家选其中一个**
- 字号比命格卡判词稍小，淡入而非弹出
- 全程无 emoji、无引导箭头、无"推荐"标记

## 二、六处节点的引导文案

### 节点一：命格落案后（已经发生）

**触发**：抽完命格、五项命数显形之后

**引导话**（**仅初临此地路径显示**）：

放在五项命数列表下方，命格判词上方：

> 客官身上有命数九两九钱，痴嗔贪惘慧各有分量。
> 铺中物事，皆以此称量。

**为什么这两句**：

- 第一句明确"九两九钱""五项分量"——校准心智模型，让玩家知道这是货币
- 第二句"皆以此称量"——预告下面要发生的事

**旧识路径**：不显示这两句，跳过。

---

### 节点二：客从何处来（分岔界面）

**触发**：玩家点击"入门问价"或类似进入按钮后

**界面**：两个选项卡

| 选项卡 | 副标题（初临此地）| 副标题（旧识老朽）|
|---|---|---|
| 来此逛逛 | 先看看铺中物事，挑一件称心的 | 雾里灯亮，随手翻一页命牌 |
| 有烦恼事欲解脱 | 取一物从身上当出，换钱再买 | 把一件放不下的东西，交给柜上称一称 |

**关键差异**：

- 初临路径用**直白说明**——告诉玩家"这两个选项的实际操作差异"
- 旧识路径用**世界观文案**（你现在游戏里已经有的版本）——保持沉浸感

---

### 节点三：入门典当界面

**触发**：玩家选"有烦恼事欲解脱"或"来此逛逛"后进入典当界面

**引导话**（**仅初临此地路径显示**）：

放在界面顶部，"哪一项命数"选择栏上方：

> 客官身上哪一份最重？
> 取出一份，老朽给你称一称，换些别的。

**为什么这两句**：

- 第一句**重新框架问题**——把"选 4 个表单字段"变成"选哪一份最重"。这把任务从填表变成自省。
- 第二句**说清楚动作的本质**——"用 A 换 B"。

**已有的损耗提示**保留（已经在 UI 上显示"一两入柜，七钱出门"）：

> 一两入柜，七钱出门。
> 罗刹海市从不做足秤买卖。

这一句两条路径都显示——它是世界观规则，不是新手教程。

---

### 节点四：货架首次打开

**触发**：典当完成、玩家第一次看到 24 件商品的货架

**引导话**（**仅初临此地路径显示**）：

在货架顶部淡入一次，玩家滚动后消失：

> 货架上每件物事，标着要几钱什么。
> 客官身上够，便取得走。

**为什么这两句**：

- 第一句解释**价格标签的读法**——"贪 3 钱"的意思是"需要花 3 钱贪"
- 第二句解释**购买条件**——"够则取，不够则不能"

**旧识路径**：不显示，玩家自己摸索。

---

### 节点五：玩家想买但命数不足

**触发**：玩家点击商品的"取此物"按钮，但对应命数不足

**引导话**（保留你之前定的）：

> 典无可典，何以为买？

**两条路径行为差异**：

| 路径 | 显示内容 |
|---|---|
| 初临此地 | 掌柜话 + UI 微提示"客官痴尚缺 2 钱" |
| 旧识老朽 | 仅显示掌柜话 |

**UI 微提示规范**（仅初临路径）：

- 出现位置：商品标签下方或灰按钮旁
- 文案模板：`客官{命数名}尚缺 {数值} 钱`
- 字号：比商品价格稍小
- 颜色：与朱砂红同色系但稍淡，避免过度警示

---

### 节点六：续签界面

**触发**：玩家完成 3 笔交易，桌上多出一支签

**引导话**：

| 路径 | 文案 |
|---|---|
| 初临此地 | "三笔已毕。<br>桌上多出一支签——抽，则再做一笔；不抽，便就此结当。<br>上签照旧，中签加倍，下签折慧。" |
| 旧识老朽 | "桌上又多一支签。" |

**关键差异**：

- 初临路径**完整说明**三种签的后果
- 旧识路径**只点画面**——"桌上又多一支签"，玩家自己悟

## 三、引导词的设计原则

以下是所有掌柜话必须遵守的原则：

### 3.1 不教学，只暗示

- ❌ "请点击这里典当"
- ❌ "您可以从这五项中选择一项作为典当物"
- ✅ "客官身上哪一份最重？"

### 3.2 只在卡点说话

不在每一步都加掌柜话。**玩家能自己走的地方，让他自己走。**

### 3.3 不重复

同一个提示在同一玩家面前最多显示一次。**第二次回到这个界面就不再显示**。

实现方式：sessionStorage 临时记一下本局已显示过的引导节点 ID，**离店后清空**。**不跨局存储**。

### 3.4 高级玩家可以跳过

不需要"跳过按钮"——选了"旧识老朽"路径就自动跳过。

### 3.5 文白比例

所有引导话采用 **半文半白**：

- ✅ "客官身上哪一份最重？"（半文，玩家能懂）
- ❌ "汝身负命数，盍择其重者而当之？"（过文，玩家看不懂）
- ❌ "您身上哪项数值最高？"（过白，破坏氛围）

判定标准：**给一个没玩过的朋友看，他要能在 3 秒内理解这句话的意思。**

## 四、两条路径的完整对照表

| 节点 | 初临此地 | 旧识老朽 |
|------|---------|---------|
| 命格落案后 | 显示"客官身上有命数九两九钱..." | 不显示 |
| 客从何处来 | 副标题用直白说明 | 副标题用世界观文案 |
| 入门典当 | 显示"哪一份最重..." + 损耗提示 | 仅显示损耗提示 |
| 货架首次 | 显示"标着要几钱什么..." | 不显示 |
| 命数不足 | 掌柜话 + 精确缺口 UI 提示 | 仅掌柜话 |
| 续签 | 完整三签解释 | "桌上又多一支签" |

**两条路径的本质差异**：

- 初临此地 = 显式说明 + 微 UI 提示
- 旧识老朽 = 纯氛围文案，玩家自己摸索

## 五、工程实现规范

### 5.1 状态管理

```typescript
// 仅本局有效，不持久化
type GuidanceMode = "novice" | "veteran";

interface GuidanceState {
  mode: GuidanceMode;
  shownNodes: Set<string>;  // 本局已显示的节点 ID
}
```

**关键约束**：

- 离店时（生成当票卡后）**完全清空**此状态
- 不写入 localStorage
- 不写入 cookie
- 不写入 fingerprint
- **不跨局识别**

### 5.2 节点 ID 列表

```typescript
const GUIDANCE_NODES = {
  AFTER_FATE_CARD: "after_fate_card",        // 命格落案后
  INTENT_FORK: "intent_fork",                 // 客从何处来
  PAWN_FIRST_TIME: "pawn_first_time",         // 入门典当首次
  SHELF_FIRST_TIME: "shelf_first_time",       // 货架首次打开
  RESOURCE_INSUFFICIENT: "resource_insufficient", // 命数不足（每次商品按钮都可触发，但每个商品仅一次）
  LOT_DRAW: "lot_draw",                        // 续签
} as const;
```

### 5.3 渲染逻辑伪代码

```typescript
function shouldShowGuidance(nodeId: string, state: GuidanceState): boolean {
  // 旧识老朽路径：除节点二、节点五的掌柜话之外，全部不显示
  if (state.mode === "veteran") {
    return ["intent_fork", "resource_insufficient"].includes(nodeId);
  }

  // 初临此地路径：本局未显示过则显示
  return !state.shownNodes.has(nodeId);
}

function markShown(nodeId: string, state: GuidanceState): void {
  state.shownNodes.add(nodeId);
}
```

### 5.4 视觉规范

- 引导话样式：与游戏内现有掌柜剪影台词相同（打字机效果、淡入淡出）
- UI 微提示样式：朱砂红同色系但稍淡（建议 #a83838，不饱和）、字号 12-13px
- 引导话和 UI 微提示**不同时显示**——避免视觉过载

### 5.5 二选一界面规范

- 出现时机：命格朱印盖落 1.5 秒后
- 出场方式：朱印效果延续，二选一界面从下方淡入
- 按钮样式：等大等距，无视觉权重差异
- 不可跳过：必须选择一个才能进入下一步
- 选择后行为：直接进入"客从何处来"界面，无中间过渡

## 六、不做的事

- 不做"任何时刻召唤掌柜"功能（v2 再考虑）
- 不做"跳过引导"按钮（旧识路径已经覆盖）
- 不做"再次提醒"机制（提示一次即足）
- 不做引导箭头、高亮、聚光灯等现代游戏 UI
- 不做语音引导
- 不做引导进度条
- 不识别用户、不存档跨局状态
- 不强制玩家观看任何动画

## 八、验收标准

升级完成后，以下场景必须通过：

- [ ] 命格落案后，必出现二选一界面
- [ ] "初临此地"路径下，6 处节点引导话全部显示
- [ ] "旧识老朽"路径下，仅"客从何处来"和"命数不足"两处显示文案
- [ ] 同一节点在同一局内仅显示一次
- [ ] 离店后，下一局重新进入时，所有引导状态清空
- [ ] 不向 localStorage、cookie、fingerprint 写入任何引导相关数据
- [ ] 二选一界面不可跳过
- [ ] UI 微提示仅在初临路径显示
- [ ] 引导话的文白比例符合"3 秒能懂"标准
