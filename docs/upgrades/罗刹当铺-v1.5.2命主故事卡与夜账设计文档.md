# 罗刹当铺 · v1.5.2 命主故事卡与夜账设计文档

> 这份文档专门给 Codex 用。
> 阅读对象：实施开发的人或 AI。
> 目标：在 v1.5 主体功能基础上，新增两件事——命主故事卡（第三张可分享卡片）+ 夜账机制（浏览器本地故事索引）。
> 本文档遵守一条核心立场：**铺子不识别你是谁，但铺子记得你来过**。

---

## 一、产品哲学

这次升级是把"故事是资产"这件事真正落地。

之前的设计（v1.5 主体）已经做到了：
- 故事在服务器永久保存
- 通过命格卡上的二维码可访问

但还差最后一块——

**玩家如何"找回自己读过的故事"？**

之前的答案是：靠玩家自己保存命格卡截图。

这个答案不够——卡片可能丢失、清掉微信记录后找不到、换设备就消失。

v1.5.2 提出新的答案：**两件事并行，但分清楚**。

| 维度 | 实现 | 立场 |
|------|------|------|
| **故事卡** | 让故事变成可下载的图片资产 | 玩家可携带 |
| **夜账** | 在玩家这台浏览器记一份故事索引 | 铺子记得你来过 |

**铺子不识别你是谁**——不绑定账号、不识别身份、换设备就忘了你。
**铺子记得你来过**——在你这台设备上，你的几次进店都被记下了。

这两件事第一次被分清楚。

## 二、命主故事卡

### 2.1 定位

命主故事卡是这家铺子的**第三张可分享卡片**。三张卡片的关系：

| 卡片 | 内容 | 何时可导出 | 传播价值 |
|------|------|----------|---------|
| 命格卡 | 命格名 + 判词 + 五项命数 + 二维码 | 命格落案后即可 | 高（吸引眼球）|
| 当票卡 | 交易记录 + 命数变化 + 临别赠言 | 离店时 | 中（玩家自留）|
| 命主故事卡 | 完整故事 + 题眼 + 二维码 | 故事生成后 | 高（耐读、可重读）|

### 2.2 版式设计

**尺寸**：3:4 竖版（朋友圈分享友好，建议 750 × 1000 px）

**视觉规范**：

- **底色**：泛黄宣纸纹理（与命格卡、当票卡视觉调性一致）
- **题眼**：朱印章风格的命格名（大字，居中或居上）
- **判词**：斜体小字，朱砂红，紧贴题眼
- **正文**：仿宋或楷体，墨黑色，行高宽松易读
- **落款**："夜账末页，掌柜落一笔朱砂：'XX'"——朱砂红，比正文小一档
- **页脚**：极淡的"罗刹当铺·一夜笔记"标记 + 域名
- **二维码**：右下角，约占卡片宽度 8-10%

**版面布局**：

```
┌─────────────────────────────┐
│                             │
│       【命格朱印章】          │
│        慧刃斩尘                │
│                             │
│  ─────────────────          │
│   你以慧为刀，                  │
│   却斩不断陈年蛛网。              │
│  ─────────────────          │
│                             │
│  丙午年某月某夜，酉时三刻。       │
│  客推门入，衣无雨，眉有霜色...    │
│                             │
│   [命主故事正文 200-280 字]    │
│                             │
│  ...转身入雾。                 │
│                             │
│  ─────────────────          │
│  夜账末页，掌柜落一笔朱砂：     │
│  "慧刃斩尘"                   │
│                             │
│  [罗刹当铺·一夜笔记]           │
│  luocha-pawnshop.vercel.app │
│                       [QR] │
│                             │
└─────────────────────────────┘
```

### 2.3 二维码设计

**位置**：右下角

**尺寸**：约占卡片宽度 8-10%（不喧宾夺主）

**内容**：完整 URL `https://luocha-pawnshop.vercel.app/story/{storyId}`

**色彩**：墨色 (#3a2818) + 纸面色 (#d4b896)，与底色调和

**功能**：朋友扫码可访问网页版故事页（含 SEO 优化版本）

### 2.4 导出时机

按之前的确认，**两个时机都允许**：

#### 时机 A：当票离店界面

与"导出当票卡"按钮并列：

```
[ 导出命格卡 ]    [ 导出当票卡 ]    [ 导出命主故事卡 ]
```

玩家可一次性导出三张卡。

#### 时机 B：命主故事页（网页版）

任何人通过二维码进入网页故事页（即朋友扫码进入的页面）后，页面提供导出按钮：

```
[ 保存这个故事 ]
```

朋友看完故事后可以导出图片，转发给更多人。

### 2.5 导出实现

前端用 `html2canvas` 将故事卡 DOM 渲染为 PNG，触发浏览器下载。

```typescript
import html2canvas from 'html2canvas';

async function exportFateStoryCard(
  storyId: string,
  storyData: FateStoryRecord
): Promise<Blob> {
  // 1. 渲染故事卡 DOM（使用专门的 export 模板）
  const cardElement = renderStoryCardForExport(storyData);
  
  // 2. 生成二维码并嵌入
  const qrUrl = `https://luocha-pawnshop.vercel.app/story/${storyId}`;
  const qrDataUrl = await QRCode.toDataURL(qrUrl, {
    width: 80,
    margin: 1,
    color: { dark: '#3a2818', light: '#d4b896' },
  });
  cardElement.querySelector('.qr-slot').src = qrDataUrl;
  
  // 3. html2canvas 截图为 PNG
  const canvas = await html2canvas(cardElement, {
    scale: 2,  // 高 DPI
    backgroundColor: null,
  });
  
  // 4. 转 Blob
  return new Promise(resolve => 
    canvas.toBlob(resolve, 'image/png', 0.95)
  );
}

async function downloadFateStoryCard(blob: Blob, fateName: string) {
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = `罗刹当铺-${fateName}-命主故事.png`;
  a.click();
  URL.revokeObjectURL(url);
}
```

**移动端**：玩家可直接长按图片保存到相册——这是浏览器原生能力，无需额外开发。

### 2.6 故事卡上不显示当票核心信息

按之前确认，故事卡保持纯粹——**不在卡上显示命数变化、交易记录等数据**。

理由：

- 故事卡的视觉重心是文字
- 数据信息已由当票卡承载
- 玩家如要数据，可一并导出当票卡——双卡互补

## 三、夜账机制

### 3.1 设计要点

夜账是浏览器本地的故事索引，让玩家能在这台设备上找回自己进过店的几次故事。

**关键约束**：

- 仅存储 storyId + 必要的展示元数据（命格名、时间、判词片段）
- 不存储任何"用户身份"——存的是故事索引，不是用户档案
- 清浏览器缓存即丢失（玩家可接受）
- 换设备/换浏览器 → 看不到（玩家可接受）
- 不写 cookie、不写 fingerprint，只写 localStorage

### 3.2 数据模型

```typescript
interface LocalStoryRecord {
  storyId: string;          // 用于跳转到 /story/{storyId}
  fateName: string;         // 命格名，如"慧刃斩尘"
  judgmentSnippet: string;  // 判词，如"你以慧为刀，却斩不断陈年蛛网"
  timestamp: string;        // 古典纪年格式，如"丙午年某月某夜子时三刻"
  visitedAt: number;        // Unix timestamp，用于排序
}

interface YezhangData {
  records: LocalStoryRecord[];  // 最多 20 条，先进先出
  version: string;              // 数据版本号，用于将来迁移
}
```

### 3.3 存储位置

```typescript
// localStorage 键名
const YEZHANG_KEY = 'luocha:yezhang';

// 写入示例
function saveToYezhang(record: LocalStoryRecord): void {
  const data: YezhangData = loadYezhang() || { records: [], version: '1.0' };
  
  // 去重（同一 storyId 只保留最新一条）
  data.records = data.records.filter(r => r.storyId !== record.storyId);
  
  // 加入新记录
  data.records.unshift(record);
  
  // 限制最多 20 条
  if (data.records.length > 20) {
    data.records = data.records.slice(0, 20);
  }
  
  localStorage.setItem(YEZHANG_KEY, JSON.stringify(data));
}

function loadYezhang(): YezhangData | null {
  try {
    const raw = localStorage.getItem(YEZHANG_KEY);
    return raw ? JSON.parse(raw) : null;
  } catch {
    return null;
  }
}

function clearYezhang(): void {
  localStorage.removeItem(YEZHANG_KEY);
}
```

### 3.4 写入时机

**自动写入**：玩家完成一局并生成命主故事后，自动调用 `saveToYezhang`。

**不需要玩家确认**——这是无感的便利功能。

**不写入的情况**：

- 玩家在 incognito/隐私模式下游戏（localStorage 不持久）
- 玩家浏览器禁用 localStorage（少数场景）
- 这两种情况下游戏照常运行，只是夜账无法保存——不报错、不打扰

### 3.5 夜账查阅入口

#### 方案 A：罗刹当铺首页加一个隐藏入口

**位置**：首页右下角或左下角，极淡的小图标（一卷书或一支签）

**视觉规范**：

- 仅在 localStorage 中存在 yezhang 数据时显示
- 不存在时（首次进店）完全不显示——保持首页的纯粹
- 图标默认半透明，hover 后高亮

**优点**：

- 不打扰新玩家
- 老玩家自然发现
- 完全隐性

#### 方案 B：进店后某处提示

**位置**：在"客从何处来"界面下方加一行小字

> "夜账上记得，客官曾来过 X 夜。" [翻看夜账]

**优点**：

- 老玩家进店就能感知
- 文学化提示符合世界观

**缺点**：

- 可能干扰新玩家的注意力
- 需要在多个地方做条件判断

**我推荐方案 A**——更克制，更符合罗刹当铺整体调性。

### 3.6 夜账界面设计

URL：`/yezhang` 或作为首页的 modal 弹层（推荐 modal，避免破坏单页流程）

**界面文案**（初临此地路径不显示此入口；旧识掌柜路径或自动识别本地有数据时可显示）：

```
[掌柜抬眼]

夜账上记得，客官曾来过几夜。

—————————————

丙午年某月某夜子时三刻
慧刃斩尘
"你以慧为刀，却斩不断陈年蛛网"
[ 翻看那一夜 ]

—————————————

丙午年另一夜亥时
惊弦引
"弦已惊弓，却不敢松手"
[ 翻看那一夜 ]

—————————————

(共 X 夜，最多记得 20 夜)

[ 清空夜账 ]
```

**视觉规范**：

- 底色与故事页一致（泛黄宣纸纹理）
- 每条记录一格，宽松排版
- 命格名朱砂红，加粗
- 判词淡墨色，斜体
- 时间戳灰色，小字
- "清空夜账"按钮置于最底部，需二次确认

**清空夜账的二次确认**：

```
[掌柜抬眼]

客官果真要忘了这几夜？
此举不可还原。

[ 是，清空 ]    [ 不，留着 ]
```

清空后，从 localStorage 完全删除 yezhang 数据。

### 3.7 与故事页的联动

玩家在夜账界面点击"翻看那一夜" → 跳转到 `/story/{storyId}`

故事页与朋友扫码进入的故事页**完全相同**——不区分"是玩家本人查看"还是"是朋友扫码查看"。这维护了"铺子不识别用户"的立场。

## 四、网页故事页（/story/[storyId]）

### 4.1 现有功能（v1.5 已规划）

- 完整展示命主故事
- 显示命格名、判词、当票缩略图
- "我也走一遭"按钮跳转到首页

### 4.2 v1.5.2 新增功能

#### 新增：导出故事卡按钮

故事页底部增加：

```
[ 保存这个故事 ]
```

任何人（玩家本人、朋友扫码进入的人）都可以导出。

实现：与 2.5 节相同的 html2canvas 导出逻辑。

### 4.3 故事页与夜账的关系

**重要**：朋友扫码进入故事页**不会写入访问者的夜账**——夜账只记录"玩家自己玩过的局"，不记录"看过的别人的故事"。

具体逻辑：

```typescript
function shouldRecordToYezhang(context: AccessContext): boolean {
  // 只在玩家完成一局后立即跳转到故事页时记录
  // 通过 URL 参数 ?from=完成局 区分
  return context.from === 'session-complete';
}
```

或更严格的实现：

- 玩家完成一局时立即写 yezhang，不依赖访问故事页
- 故事页本身不触发任何 yezhang 写入

后一种方案更干净，**推荐使用**。

### 5.4 错误处理

#### localStorage 不可用

```typescript
function isLocalStorageAvailable(): boolean {
  try {
    const test = '__test__';
    localStorage.setItem(test, test);
    localStorage.removeItem(test);
    return true;
  } catch {
    return false;
```

不可用时：

- 不显示首页夜账入口

不阻塞玩家正常游戏。

## 七、跨平台迁移就绪性

### 7.1 核心数据的可迁移性

故事数据存储在服务器（Vercel KV），未来转其他平台时：

- KV 数据可一键导出 JSON
- 通过 v1.5 主体文档已规划的存储抽象层迁移

### 7.2 夜账数据的迁移问题

localStorage 数据**天然不可跨设备**，这是这次设计的接受前提。

但提供一个临时迁移工具：

```
/yezhang/export
  → 导出当前夜账为 JSON 文本

/yezhang/import
  → 玩家在另一台设备粘贴 JSON 文本，导入到该设备
```

这是个**纯客户端工具**——只是把 JSON 在 localStorage 之间搬移。不涉及账号、不涉及服务器。

是否实施由你判断——这是 nice-to-have，不是 must-have。

### 7.3 转微信小程序的考虑

微信小程序的本地存储是 `wx.setStorage`，逻辑与 localStorage 类似。代码迁移时只需替换存储调用。
